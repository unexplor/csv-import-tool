# 商品 CSV 导入工具

Python 3.10+，仅使用标准库，不需要 pip 安装依赖。面向本机使用，监听 127.0.0.1。

## 启动

先克隆仓库并进入目录（或在 GitHub 下载 ZIP 后进入解压目录）：

```sh
git clone https://github.com/unexplor/csv-import-tool.git
cd csv-import-tool
```

Windows PowerShell：

```powershell
python app.py
```

macOS / Linux 可使用 `python3 app.py`，运行测试时相应使用 `python3 -m unittest -v`。

浏览器打开 http://127.0.0.1:8000，选择 CSV，查看预览后点击“导入有效记录”。Ctrl+C 停止。
首次启动自动创建同目录的 `products.db`，重启保留数据。

如果 8000 端口已被占用，使用：

```powershell
python app.py --port 8001
```

也可以指定已有目录下的数据库路径：`python app.py --db ./my-products.db`。
下载压缩包到其他目录时，先进入解压目录再执行相同命令。

## 测试

```powershell
python -m unittest -v
```

测试使用临时数据库，不修改实际商品数据；覆盖字段校验、全部重复行标错、BOM、CRLF、逗号、跨行名称、转义引号、空行、列数错误、错误编码与表头、未闭合引号、精确价格、大整数库存、新增更新、幂等导入、事务回滚及真实 HTTP 请求。

## 示例与预期结果

`samples/mixed.csv` 含以下内容（多行名称是一条记录）：

```csv
code,name,price,stock
A001,苹果,3.50,10
A002,"礼盒,豪华版",25.00,5
A003,"多行商品
第二行名称",9.99,2
DUP,重复商品甲,1.00,1
DUP,重复商品乙,2.00,2
,缺少编码,1.00,1
A004,   ,1.00,1
A005,负价格,-1.00,1
A006,三位小数,1.234,1
A007,小数库存,1.00,1.5
A008,负库存,1.00,-1
A009,"他说""你好""",0,0
```

从空数据库开始：

| 操作 | 预期 |
| --- | --- |
| 预览 mixed.csv | 共 12 条，有效 4 条，错误 8 条 |
| 查看 A003 | 物理行号 4–5，名称保留换行 |
| 查看 DUP | 原始第 6、7 行均为错误 |
| 首次导入 mixed.csv | 新增 4，跳过 8，共 4 个商品 |
| 再次导入 mixed.csv | 新增 0，更新 0，未变化 4，共 4 个商品 |
| 导入 update.csv | 更新 A001、新增 A010，共 5 个商品 |
| 再次导入 update.csv | 新增 0，更新 0，未变化 2，共 5 个商品 |

`samples/update.csv`：

```csv
code,name,price,stock
A001,苹果（更新）,4.20,20
A010,新增商品,6.00,3
```

## 规则说明

- 表头严格为 `code,name,price,stock`，顺序固定；UTF-8 编码，允许 BOM，最大 5 MiB。
- 字段去除首尾空白后校验；名称内部逗号、换行和引号保留。编码区分大小写。
- 编码和名称不能为空。价格接受 `0`、`1.2`、`1.23` 等十进制数字，不接受负数、指数、正号、`.5` 或 `1.`。库存只能由 ASCII 数字组成。
- 重复判定覆盖整个文件，即使其中某行还有其他错误，所有相同非空编码行仍全部报错。
- 总行数指表头以外的 CSV 逻辑记录数，多行名称只算一条。空行计作错误记录，文件最后的正常换行不额外计数。
- 每行显示原文件物理行号、字段及错误原因。列数错误和业务错误不影响其他记录预览或导入。
- 引号使用 CSV 规则：字段带逗号或换行时用双引号包围，内部双引号写成两个双引号。未闭合引号会令后续文本归入同一个损坏记录，无法可靠猜测其原始边界；已解析记录仍可预览和导入。
- 导入接口重新校验文件，只写入有效记录。SQLite 编码主键和 UPSERT 保证不存在重复商品；数据库写入异常则回滚本次全部写入。
- 价格以精确十进制文本保存为两位小数，库存以规范化整数文本保存，避免浮点误差和 64 位整数溢出。
- 上传文件和预览仅在内存中处理，只有确认导入后商品才持久化。页面使用 `textContent` 显示 CSV 内容。

文件：`app.py` 为完整服务和页面；`test_app.py` 为自动化测试；`samples/` 为可直接上传的样例。
